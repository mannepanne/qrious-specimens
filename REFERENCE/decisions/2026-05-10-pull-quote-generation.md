# ADR: Pull-quote generation as a separate text-only Claude follow-up call

**Date:** 2026-05-10
**Status:** Active
**Supersedes:** N/A

---

## Decision

Generate the Gazette pull-quote with a **second**, **text-only** Claude Haiku call that runs sequentially after the multimodal field-notes call, rather than asking the field-notes call to produce both outputs in a single response. Failure of the pull-quote call is soft — discovery completes, `pull_quote = null` is persisted, and the Gazette renderer falls back to a truncated excerpt.

## Context

The Field Dispatches redesign of the Gazette feed needs one short evocative line per discovery to anchor each dispatch card (featured, compact). Field notes are 2–4 paragraphs and the existing renderer already truncates them as a fallback, but the result reads like a paragraph cut mid-sentence rather than a quote — flat, redundant with the body copy beneath it, and visually unbalanced against the italic / smallcaps layout the redesign needs.

Two production constraints shape the choice:

1. **One source of truth for the prose**: field notes already live in `species_images.field_notes` and back the species page, the catalogue card, and the cabinet detail. Whatever produces the pull-quote must be derivable from that prose, not generated independently from the DNA, otherwise the quote and the body drift apart over time.
2. **Discovery latency budget is tight**: end-to-end scan-to-card already runs Gemini → CF Images → Claude (field notes). Adding a second sequential Haiku call costs ~600–900ms; that's measurable but acceptable. Anything that would block discovery on the second call is not.

A backfill is also required for the ~20 existing rows that have field notes but no pull-quote. The backfill must produce statistically comparable output to the live worker (otherwise the variety guard regresses on partial corpora).

## Alternatives considered

- **Single multimodal call returning both outputs delimited (e.g. `<<FIELD_NOTES>> … <<PULL_QUOTE>> …`):**
  - Why not: Two unrelated tuning targets ride on the same prompt. Field notes want a Victorian naturalist register over 2–4 paragraphs; pull-quotes need a single self-contained line with strict opener-shape variety (TD-031 calibration uses a 35% per-shape cap and a 35% top-first-word cap). Tuning the prompt to satisfy both at once means every regression in one degrades the other. The delimited-parsing path is also fragile — a missing or malformed delimiter forces a retry of the whole multimodal call (image + 300+ tokens) just to recover the text-only line.

- **Single call producing field notes only; render-time excerpt only (status quo extended):**
  - Why not: Renders a sentence-fragment that visually competes with the body copy beneath it. The dispatch card's whole point is contrast — italic quote sitting above smallcaps prose — and a paragraph head used as both quote and intro defeats it.

- **Generate pull-quote from DNA at scan time, independent of field notes:**
  - Why not: Decouples the quote from the body copy, so when field-note prompts iterate the quote no longer mirrors the prose underneath. Loses the "this line could plausibly have been said about this specimen" feel.

- **Chosen: Sequential text-only follow-up call after field notes, soft-fail:**
  - Why this won: Pull-quote prompt iterates independently (the trial harness `scripts/trial-pull-quotes.ts` reuses `generatePullQuote()` directly, identically to production). Backfill script reuses the same function and prompt, so regenerating a missing quote produces the same statistical distribution as a live discovery. Failure path is structurally simple — `pullQuote: null` returned, render-time excerpt covers the gap, no retry orchestration needed.

## Reasoning

**Symmetry with the backfill is the load-bearing argument.** The corpus regression test (`workers/generate-creature/pullQuote.test.ts`) asserts opener-shape variety against `scripts/output/trial-pull-quotes.json`. That file is regenerated by running the trial harness over the historical field-notes corpus. If the production pull-quote call shape differed from the trial-harness call shape (e.g. multimodal vs text-only, or combined vs separate), the trial output would not be representative and the variety guard would lose its calibration — opener-shape attractors that the live worker hits would be invisible to CI.

By making both production and trial use the identical `generatePullQuote(prompt, apiKey)` function, the regression test is genuinely guarding the production path. The same applies to the backfill: rows backfilled today must look statistically like rows generated tomorrow, otherwise the variety distribution on the Gazette feed becomes bimodal as the backfilled / live ratio shifts.

**Independent prompt tuning** is the second factor. The existing field-notes prompt (`buildClaudePrompt`) carries a directive rotation already (TD-031); the pull-quote prompt (`buildPullQuotePrompt`) carries its own 6-way directive rotation seeded by `dna.seed`. Keeping these prompts in separate files and separate API calls means iterating one cannot regress the other — and both have corpus regression tests that would catch drift.

**Robust parsing** falls out naturally. `generatePullQuote()` strips markdown headers, surrounding straight or curly quote marks, and stray whitespace. Adding that logic to a delimited-parser inside `generateFieldNotes()` would mix two output schemas in one parser; here each function parses one well-defined response.

**Soft-fail is correct:** the pull-quote is decorative. The render-time fallback (`excerptFromFieldNotes()` in `src/lib/feedDate.ts`) produces a usable card without it. The cost of treating pull-quote failure as fatal would be users seeing a generation error and losing their specimen for what is fundamentally a presentation refinement.

## Trade-offs accepted

**Two API calls per discovery instead of one.** Adds ~600–900ms to the discovery latency budget on the cold-cache path. Cached scans are unaffected because the cached row already includes `pull_quote`. Accepted because the worker's scan-to-card path is dominated by Gemini latency anyway, and the redesign's UX value (clear visual contrast on every dispatch card) materially exceeds the cost.

**Two prompts to maintain.** Field-notes prompt and pull-quote prompt evolve independently. Accepted because both have regression tests guarding their key contracts (uniformity, opener-shape variety, no rarity vocabulary in pull-quotes). The duplication is shallow — prompt builders share no logic.

**Soft-fail can persist nulls in production.** A row with `field_notes` populated but `pull_quote IS NULL` will continue to fall through to the render-time excerpt indefinitely until the backfill is re-run. Accepted because the backfill is idempotent and trivially re-runnable; transient Anthropic outages do not warrant retry orchestration in the discovery path.

**Pull-quote and field-notes can drift in tone.** The pull-quote is generated from the field notes (so it can't drift in *fact*) but the prompt's directive rotation might emphasise an aspect the body copy doesn't open with. Accepted because that's exactly the desired effect — the quote draws the eye to a different facet, not a redundant restatement.

## Implications

**Enables:**
- Independent prompt iteration with isolated corpus regression tests for each output.
- A trial-and-backfill loop that produces output statistically identical to live traffic, because every path through the system uses the same function.
- A render-time excerpt fallback that's mechanically simple (`excerptFromFieldNotes`) rather than orchestrated retry behaviour.
- Future enrichments (e.g. species-page quote-of-the-day) can pull `pull_quote` directly from the existing column with no extra generation step.

**Prevents/complicates:**
- Cannot revert to a single-call shape without invalidating the corpus regression tests and the backfill calibration. A revert would need to either drop those tests or rebuild them around a delimited parser.
- Anthropic API contract is now hit twice per cold discovery — small but real exposure to provider rate-limit changes.
- Backfill operator must remember the seed-resolution step (`fetchSeedMap()`); without it the lead-directive rotation collapses to "always directive 0" and the backfilled rows would show a visible opener-shape attractor on the Gazette feed. This is documented in the script header.
